# ADR-0001: GitHub Pages와 Jekyll 채택

- 상태: Accepted
- 날짜: 2026-09-08

## 맥락

개인 학습 기록을 계속 추가하면서 GitHub 이외의 호스팅, 데이터베이스 또는 관리 도구를 운영하지 않아야 한다. 글 작성 비용이 낮고 디자인을 직접 수정할 수 있어야 한다.

## 고려한 선택지

1. HTML 파일 직접 작성
2. Jekyll과 Markdown
3. React/Vite 정적 빌드

## 결정

메인 스터디 아카이브에는 Jekyll과 Markdown을 채택한다. GitHub Pages가 직접 지원하고, 게시물 파일과 화면 템플릿을 분리해 기록이 늘어나도 반복 작업이 적기 때문이다.

## 결과

### 긍정적

- 새 글은 Markdown 파일 하나로 게시할 수 있다.
- 별도 서버와 데이터베이스가 필요 없다.
- HTML과 CSS를 직접 수정해 고유한 디자인을 유지할 수 있다.

### 부정적

- 로그인, 댓글, 서버 검색 같은 동적 기능을 직접 제공할 수 없다.
- 로컬 미리보기에는 Ruby와 Bundler가 필요하다.
- Jekyll과 Liquid 문법을 일부 익혀야 한다.

### 후속 작업

- 실제 저장소 이름을 확정하고 `url`, `baseurl`을 설정한다.
- 첫 배포 후 모바일과 키보드 탐색을 확인한다.
